# Validation — version 1.0.1

Validation performed in the build environment on 2026-10-18, using Node.js
24.19.0 and system FFmpeg/ffprobe. Runtime artifacts are plain JavaScript.

## Automated checks

The test suite uses actual local UDP/TCP sockets, the original Python protocol
and camera emulator from the supplied HA 0.3.0 archive, actual Homebridge/HAP
classes, and actual FFmpeg processes. Xiaomi account services are mocked.

- Published NaCl/X25519, RFC 8439 ChaCha20 and RFC 6229 RC4-drop vectors.
- Malformed crypto data, invalid curve points and truncated media rejection.
- Authentication credentials collected from JSON, cookies and redirect headers.
- Rejection of non-Xiaomi authentication redirects without secret disclosure.
- Independent verification of cloud signatures and encrypted cloud responses.
- Password/CAPTCHA and email-code verification with simulated account responses.
- Device-list pagination, camera filtering and cookie scoping/serialization.
- Refresh from a saved account credential with a corrupt cached security key.
- Node.js MISS interoperability with the original Python peer over UDP and TCP.
- UDP packet reordering, duplicate delivery, sequence wrap and buffer bounds.
- Camera authentication, source quality, keepalive and all four motor operations.
- A control-only session sends a motor command without starting video.
- H.264 and H.265 MPEG-TS streams decoded by FFmpeg and inspected by ffprobe.
- Monotonic output timestamps despite repeated, backward and discontinuous clocks.
- H.265 camera snapshots are real JPEGs; equal concurrent requests share work.
- Video and pan/tilt reuse one authenticated camera connection.
- Idle capture closes the camera connection.
- **1920×1080 H.265 input becomes decryptable 1280×720 H.264 SRTP output**,
  decoded by a separate FFmpeg process using the negotiated SRTP key and salt.
- HomeKit stream setup, actual RTP output and stop cleanup.
- HomeKit resolution advertisement preserves 720p at 15 fps and enforces height caps.
- Secret-bearing media URLs are served only on loopback and require GET.
- Real Homebridge camera services, external publication, selection and exclusions.
- Stable accessory UUIDs and no placeholder camera rows in generated configuration.
- Private, atomic credential storage and path traversal rejection.
- Custom UI verification flow, password clearing and saved camera selections.
- UI refresh preserves names, IP overrides and excluded selections.
- Custom UI server starts through the real Homebridge IPC protocol.
- Per-camera pairing metadata is private and contains no setup codes or signing keys.
- The pairing panel reads only this plugin's published cameras and actual HAP records.
- QR images decode to the exact setup URI generated by the real HAP accessory API.
- Pairing status refreshes from saved HomeKit clients without changing those records.
- Pairing codes and copy buttons work even when Xiaomi authentication fails.
- Browsers without clipboard permission can select the code for manual copying.
- Stopped, unpublished or invalid records do not produce guessed pairing codes.

All **40 tests passed** with Homebridge 2.4.0. The Homebridge registration, pairing and
streaming subset also passed all **14 tests** with Homebridge 1.11.1. The UI tests exercise
the DOM in jsdom and the real custom UI IPC server; they are not visual browser
or full Homebridge UI installation tests.

## Not yet validated on physical hardware

- A live Xiaomi account login, CAPTCHA/SMS/email delivery and token renewal.
- Camera provisioning and streaming against physical C200, C301 or Mi 360 2K
  cameras from this Node.js plugin.
- Physical pan/tilt movement and direction on each camera's firmware.
- Accessory pairing and live viewing on an actual iPhone, Mac or Apple TV.
- HomeKit remote viewing through an Apple home hub.
- Actual startup latency, long-duration reliability, CPU and memory use on the
  user's Homebridge LXC host.

The supplied Home Assistant implementation's successful hardware observations
do not establish hardware verification of this separate Node.js port.

## Suggested first hardware check

Install the TGZ, configure Europe (`de`) or your Mi Home region, and select one
camera. Close its other live streams, restart Homebridge, pair that external
camera in Apple Home and check its thumbnail and live video. Activate one
movement control while live video is open. Close live view and confirm the
camera stops after the configured idle period. Then enable the other cameras.

Source ZIP contains all test code and the original peer fixtures. The runtime
npm TGZ excludes tests, Python and development dependencies. No live account
credentials or camera recordings are included.
